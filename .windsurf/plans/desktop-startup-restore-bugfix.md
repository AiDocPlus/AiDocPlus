# Desktop 启动恢复异常修复计划

## 目标

- 修复应用启动时原有项目与已打开文档未自动恢复的问题。
- 保持现有 workspace-state 数据结构兼容，不破坏已有状态文件。

## 分析结论

- 当前 `App.tsx` 将“资源预加载”和“工作区恢复”放在同一个 `try` 中。
- 一旦 `loadPlugins()`、模板加载等任一预加载失败，就会直接进入 fallback，只执行 `loadProjects()`，从而跳过 `restoreWorkspace()`。
- 这会表现为：项目列表可能加载出来，但原有项目不会自动打开，原有文档/标签页也不会恢复。

## 修复步骤

1. 将应用初始化拆为两个独立容错阶段：
   - 资源预加载阶段
   - 工作区恢复阶段
2. 资源预加载失败时仅记录日志，不阻断后续 `restoreWorkspace()`。
3. 仅当工作区恢复本身失败时，才退回到 `loadProjects()`。
4. 验证启动流程在预加载异常时仍能恢复旧项目与文档。

## 约束

- 不修改 workspace-state 文件格式。
- 不改变项目/文档数据模型。
- 不引入前端接口变更。
